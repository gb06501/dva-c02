### 1.2.2 Configure Lambda functions by defining environment variables and parameters

#### 1.2.2.1 Exam Context

##### 1.2.2.1.1 Skill Scope
- DVA-C02 Skill 1.2.2 requires configuring Lambda functions by defining environment variables and parameters.
- The exam guide explicitly names memory, concurrency, timeout, runtime, handler, layers, extensions, triggers, and destinations as examples.
- AWS Lambda is explicitly in scope for DVA-C02.
- This skill is about understanding which Lambda configuration control changes which aspect of function behavior.

##### 1.2.2.1.2 Core Mental Model
- Lambda behavior is determined by both code and configuration.
- Configuration controls execution resources, runtime behavior, integrations, and operational characteristics without necessarily changing application code.
- Mental model: code package/container image + runtime/handler + resources + environment/configuration + triggers + destinations = deployed Lambda behavior.

#### 1.2.2.2 Environment Variables

##### 1.2.2.2.1 Purpose
- Environment variables let function behavior vary without modifying source code.
- Lambda stores configured environment variables as version-specific function configuration.
- The runtime exposes them to the function process.

##### 1.2.2.2.2 Typical Uses
- Environment name such as dev/test/prod.
- Feature/configuration flags.
- Resource identifiers.
- Non-secret endpoint/configuration values.
- Region-specific or environment-specific settings.

##### 1.2.2.2.3 Sensitive Values
- AWS recommends Secrets Manager rather than Lambda environment variables for sensitive information such as database credentials, API keys, or authorization tokens.
- Environment variables can be encrypted at rest, but secret lifecycle and rotation are better handled through managed secret services.

##### 1.2.2.2.4 Version Behavior
- Environment-variable configuration is associated with the function version.
- When a Lambda version is published, version-specific configuration is locked.
- Updating `$LATEST` environment variables does not mutate already published versions.

##### 1.2.2.2.5 Limits
- AWS currently documents an aggregate 4 KB quota for function environment variables.

#### 1.2.2.3 Runtime

##### 1.2.2.3.1 Runtime Purpose
- The runtime provides the language-specific execution environment for Lambda code.
- Lambda-supported runtimes handle communication with the Lambda Runtime API.
- Examples include Node.js, Python, Java, .NET, and other currently supported runtimes.

##### 1.2.2.3.2 Managed Runtime
- AWS manages supported runtime versions.
- Runtime choice affects language version, available runtime libraries, lifecycle support, and deployment compatibility.

##### 1.2.2.3.3 Custom Runtime
- Lambda supports custom runtimes when the required language/runtime is not provided directly.
- A custom runtime communicates with the Lambda Runtime API.
- Prefer managed runtimes when they satisfy the requirement.

#### 1.2.2.4 Handler

##### 1.2.2.4.1 Handler Purpose
- The handler is the entry point Lambda invokes for each event.
- Handler configuration identifies the function/method that receives the event and context.
- Exact handler syntax depends on the runtime.

##### 1.2.2.4.2 Handler Responsibilities
- Parse and validate incoming events.
- Invoke application/business logic.
- Return the response expected by the invocation model.
- Keep handlers thin where practical so business logic remains independently testable.

#### 1.2.2.5 Memory

##### 1.2.2.5.1 Memory Allocation
- AWS currently supports 128 MB to 10,240 MB in 1-MB increments.
- Memory controls more than RAM: Lambda allocates CPU proportionally to configured memory.

##### 1.2.2.5.2 CPU Relationship
- Increasing memory also increases available CPU and related resources.
- CPU-bound functions can become faster even when they do not need more RAM.
- Detailed optimization belongs to Skill 1.2.6.

#### 1.2.2.6 Timeout

##### 1.2.2.6.1 Function Timeout
- Timeout defines the maximum duration of one invocation.
- AWS currently documents a maximum of 900 seconds (15 minutes).
- Lambda terminates the invocation when the timeout is reached.

##### 1.2.2.6.2 Selection
- Set timeout above realistic worst-case processing while keeping failure detection reasonably fast.
- Downstream client timeouts should usually be shorter than the function's remaining execution time.

#### 1.2.2.7 Concurrency

##### 1.2.2.7.1 Concurrency
- Lambda concurrency is the number of in-flight function invocations being processed simultaneously.
- Concurrency affects scaling, downstream load, quotas, and throttling.

##### 1.2.2.7.2 Unreserved Concurrency
- Functions use the shared account/Region concurrency pool unless reserved concurrency is configured.
- Exhaustion of available concurrency causes throttling.

##### 1.2.2.7.3 Reserved Concurrency
- Reserved concurrency allocates concurrency exclusively to a function and also sets its upper scaling bound.
- It can protect capacity for critical functions.
- It can protect downstream resources by limiting concurrent invocations.
- AWS currently documents no additional charge for reserved concurrency.

##### 1.2.2.7.4 Provisioned Concurrency
- Provisioned concurrency pre-initializes execution environments before requests arrive.
- It reduces cold-start latency.
- It incurs additional cost.
- It is configured on a published version or alias, not `$LATEST`.

##### 1.2.2.7.5 Reserved vs Provisioned
- Reserved concurrency: capacity isolation/control.
- Provisioned concurrency: startup-latency control.

#### 1.2.2.8 Layers

##### 1.2.2.8.1 Layer
- A Lambda layer is a ZIP archive containing supplementary code or data.
- Typical contents include shared libraries, dependencies, custom runtimes, configuration files, or tooling.

##### 1.2.2.8.2 Benefits
- Separate application logic from shared dependencies.
- Share dependencies across functions.
- Reduce duplication across deployment packages.
- Version shared dependency content independently.

##### 1.2.2.8.3 Limits
- AWS currently allows up to five layers attached to a function.

#### 1.2.2.9 Extensions

##### 1.2.2.9.1 Extension Purpose
- Lambda extensions augment the execution environment.
- Common uses include observability, monitoring, security, secrets/configuration retrieval, and governance.

##### 1.2.2.9.2 Internal Extension
- Runs as part of the runtime process.

##### 1.2.2.9.3 External Extension
- Runs as a separate process in the execution environment.
- Participates in the execution-environment lifecycle.

##### 1.2.2.9.4 Resource Impact
- Extensions share execution-environment resources with the function.
- They can increase memory/CPU use and init/invocation duration.

#### 1.2.2.10 Triggers and Event Sources

##### 1.2.2.10.1 Trigger
- A trigger is a configured source that causes Lambda to be invoked.
- Invocation behavior depends on the integration.

##### 1.2.2.10.2 Synchronous Invocation
- Services such as API Gateway can invoke Lambda synchronously.
- The caller waits for a result.

##### 1.2.2.10.3 Asynchronous Invocation
- Some AWS services invoke Lambda asynchronously.
- Lambda accepts the event and manages asynchronous retry behavior.
- Detailed asynchronous error handling belongs to Skill 1.2.3.

##### 1.2.2.10.4 Event Source Mapping
- Lambda uses event source mappings for poll/stream sources such as SQS or Kinesis.
- Configuration can control batch size, filtering, starting position, concurrency, and failure behavior depending on source.

#### 1.2.2.11 Destinations

##### 1.2.2.11.1 Lambda Destinations
- Lambda Destinations route asynchronous invocation results to another supported destination.
- Success and failure destinations can be configured independently.
- The destination receives an invocation record with request/response context.

##### 1.2.2.11.2 Scope Boundary
- Detailed destination, retry, and DLQ behavior belongs to Skill 1.2.3.

#### 1.2.2.12 Versions and Aliases

##### 1.2.2.12.1 Published Version
- Publishing a version creates an immutable snapshot of function code and eligible configuration.

##### 1.2.2.12.2 `$LATEST`
- `$LATEST` is the mutable working version.
- Provisioned concurrency cannot be configured directly on `$LATEST`.

##### 1.2.2.12.3 Alias
- An alias is a named pointer to a published version.
- Aliases can provide stable environment names and support traffic shifting.
- Detailed deployment use belongs to Domain 3.

#### 1.2.2.13 Ephemeral Storage

##### 1.2.2.13.1 `/tmp`
- Lambda provides configurable temporary local storage at `/tmp`.
- It is useful for temporary files, decompression, local transformations, and caching during execution.
- It is not durable application persistence.

#### 1.2.2.14 File System

##### 1.2.2.14.1 Amazon EFS
- Lambda can mount Amazon EFS for shared persistent file storage.
- EFS access requires VPC connectivity and an EFS access point.
- VPC access is covered by Skill 1.2.1.

#### 1.2.2.15 Execution Role

##### 1.2.2.15.1 Execution Role
- Every Lambda function uses an IAM execution role.
- Lambda assumes the role while running function code.
- The role controls which AWS API operations the function can perform.
- Detailed IAM design belongs to Domain 2.

#### 1.2.2.16 Logging and Tracing

##### 1.2.2.16.1 CloudWatch Logs
- Lambda integrates with CloudWatch Logs when the execution role permits logging.

##### 1.2.2.16.2 X-Ray
- Lambda supports AWS X-Ray tracing.
- Detailed observability belongs to Domain 4.

#### 1.2.2.17 Configuration Decision Model

##### 1.2.2.17.1 Need Environment-Specific Behavior
- Use environment variables or an appropriate configuration service.
- Use Secrets Manager for sensitive secrets.

##### 1.2.2.17.2 Function Is CPU/Memory Constrained
- Increase memory and remeasure duration and cost.
- Remember CPU scales with memory.

##### 1.2.2.17.3 Function Runs Too Long
- Configure an appropriate function timeout.
- Keep downstream client timeouts below the function timeout.

##### 1.2.2.17.4 Need to Protect Downstream Capacity
- Use reserved concurrency to limit maximum concurrent invocations.

##### 1.2.2.17.5 Need Predictable Low Startup Latency
- Consider provisioned concurrency.

##### 1.2.2.17.6 Need Shared Dependencies
- Consider Lambda layers for ZIP-based functions.

##### 1.2.2.17.7 Need Runtime Augmentation
- Consider a Lambda extension.

##### 1.2.2.17.8 Need Invocation from AWS Event
- Configure the appropriate trigger/event source mapping.

##### 1.2.2.17.9 Need Post-Processing for Async Invocation
- Configure a Lambda Destination.

#### 1.2.2.18 Important Distinctions

##### 1.2.2.18.1 Memory vs Ephemeral Storage
- Memory is RAM and influences CPU allocation.
- Ephemeral storage is local `/tmp` disk capacity.

##### 1.2.2.18.2 Reserved vs Provisioned Concurrency
- Reserved concurrency isolates/limits capacity.
- Provisioned concurrency pre-initializes environments.

##### 1.2.2.18.3 Layer vs Extension
- Layer packages shared code/data/dependencies.
- Extension augments runtime/execution behavior.

##### 1.2.2.18.4 Trigger vs Destination
- Trigger determines what starts the function.
- Destination determines where asynchronous results go afterward.

##### 1.2.2.18.5 Runtime vs Handler
- Runtime is the language execution environment.
- Handler is the application entry point.

##### 1.2.2.18.6 Environment Variable vs Secret
- Environment variable is general configuration.
- Secrets Manager is the preferred managed service for sensitive secrets.
