### 1.1.11 Use Amazon Q Developer to assist with development

#### 1.1.11.1 Exam Context

##### 1.1.11.1.1 Skill Scope
- DVA-C02 Skill 1.1.11 explicitly requires using Amazon Q Developer to assist with development.
- Amazon Q Developer was added as an in-scope service in Version 2.1 of the DVA-C02 exam guide.
- This skill is about applying Amazon Q Developer during software development rather than understanding generative AI architecture in general.
- The exam guide also identifies AI-assisted development as an emerging topic, including code generation, review, optimization, refactoring, security scanning, and test generation.

##### 1.1.11.1.2 Core Mental Model
- Amazon Q Developer is a generative AI assistant for software development and AWS workloads.
- In development environments it can understand code context, answer development questions, generate or modify code, review code, identify security and quality issues, refactor code, and assist with upgrades.
- Treat Amazon Q as a development assistant whose output must be reviewed and validated, not as an authoritative replacement for application requirements, testing, security controls, or developer judgment.

#### 1.1.11.2 Development Surfaces

##### 1.1.11.2.1 IDE
- Amazon Q Developer integrates with supported IDEs.
- Current AWS documentation lists Visual Studio Code, JetBrains IDEs, Eclipse, and Visual Studio among supported IDE environments, with feature availability varying by IDE.
- IDE capabilities include chat, workspace context, inline suggestions, agentic coding, code review, and transformations where supported.
- The IDE is the most important surface for this development-focused skill.

##### 1.1.11.2.2 Command Line
- Amazon Q Developer also provides command-line development capabilities.
- Command-line use can assist with software-development workflows without requiring all interaction to happen inside an IDE.
- Exact CLI capabilities evolve quickly; understand the role rather than memorizing transient UI commands unless explicitly required by AWS exam material.

##### 1.1.11.2.3 AWS Experiences
- Amazon Q Developer is also available in AWS-related experiences outside the IDE.
- Those capabilities can assist with understanding AWS resources, architecture, documentation, and operational tasks.
- For Skill 1.1.11, prioritize development assistance rather than broad AWS-console assistance.

#### 1.1.11.3 Chat About Code

##### 1.1.11.3.1 Development Questions
- Developers can ask Amazon Q questions about code and software-development tasks.
- Amazon Q can explain code, programming concepts, AWS usage, and implementation approaches.
- Questions can use the context available from the current file or workspace depending on the feature and IDE.

##### 1.1.11.3.2 Explain Existing Code
- Amazon Q can explain unfamiliar or complex code.
- This is useful when understanding an existing codebase, AWS SDK usage, application flow, or implementation decisions.
- Generated explanations should be checked against the actual source code and requirements.

##### 1.1.11.3.3 AWS Development Guidance
- Amazon Q can answer questions about building applications on AWS.
- It can provide guidance based on AWS concepts, services, APIs, and development practices.
- Service-specific implementation decisions should still be verified against current official AWS documentation when correctness matters.

#### 1.1.11.4 Inline Code Suggestions

##### 1.1.11.4.1 Real-Time Suggestions
- Amazon Q Developer can generate code recommendations while the developer writes code.
- Suggestions use existing code, comments, and other available context.
- Suggestions can range from small completions to larger code blocks or functions.

##### 1.1.11.4.2 Developer Control
- Generated suggestions are proposals.
- The developer decides whether to accept them.
- Review generated code for correctness, security, maintainability, dependencies, and alignment with project requirements before accepting it.

##### 1.1.11.4.3 Comments as Intent
- Comments can describe intended behavior and provide context for code generation.
- Clear intent and surrounding code help Amazon Q generate more relevant suggestions.
- Generated implementation still requires verification through review and testing.

#### 1.1.11.5 Inline Chat

##### 1.1.11.5.1 Selected-Code Interaction
- Inline chat allows a developer to select code and give Amazon Q an instruction directly from the coding window.
- Amazon Q generates a proposed code change and displays it as a diff.
- The developer can review and accept or reject the generated change.

##### 1.1.11.5.2 Typical Uses
- Fix code.
- Refactor selected code.
- Document code.
- Generate unit tests.
- Make focused changes without switching away from the editor.

##### 1.1.11.5.3 Context Boundary
- AWS documents inline chat as using the current file as context for the recommendation.
- Do not assume every Amazon Q feature automatically has identical repository-wide context.
- Context scope depends on the feature being used.

#### 1.1.11.6 Agentic Coding

##### 1.1.11.6.1 Coding Partner
- Current Amazon Q Developer IDE documentation provides agentic coding capabilities.
- A developer can describe a development task in natural language.
- Amazon Q can reason about the task, use project/workspace context, and make changes to project files.
- This supports larger tasks than simple line completion.

##### 1.1.11.6.2 File Changes
- Agentic coding can modify project files directly.
- Changes remain reviewable by the developer.
- Use diffs and version control to understand exactly what changed before committing generated work.

##### 1.1.11.6.3 Iteration
- Developers can continue providing instructions while working with Amazon Q.
- Development therefore becomes iterative: describe goal → inspect generated changes → provide corrections/context → validate result.
- Good results depend on clearly communicating requirements and constraints.

##### 1.1.11.6.4 Tool and Command Interaction
- Agentic coding can suggest shell commands and, depending on configuration and risk classification, may execute appropriate commands.
- Treat command execution as a consequential action.
- Review commands and their effects, particularly when they can modify infrastructure, credentials, files, dependencies, or remote systems.

#### 1.1.11.7 Generate and Modify Code

##### 1.1.11.7.1 New Code
- Amazon Q can generate new application code from natural-language requirements.
- Generated code can use existing project context where the selected feature supports it.
- It can assist with both AWS-specific and general software-development tasks.

##### 1.1.11.7.2 Existing Code
- Amazon Q can update existing implementations.
- Typical tasks include adding functionality, fixing defects, restructuring code, or applying requested changes.
- Existing tests and project conventions should be used to validate generated modifications.

##### 1.1.11.7.3 Refactoring
- Amazon Q can suggest and perform refactoring.
- Refactoring should preserve intended externally observable behavior unless a behavioral change is explicitly requested.
- Run tests after generated refactoring and inspect the diff for unintended changes.

##### 1.1.11.7.4 Debugging
- Amazon Q can assist in understanding and fixing defects.
- Give it relevant code, errors, logs, stack traces, and requirements as context where appropriate.
- A plausible generated fix is not evidence that the root cause is correct; reproduce and verify the defect.

#### 1.1.11.8 Generate Unit Tests

##### 1.1.11.8.1 Test Generation
- Amazon Q Developer can generate unit tests for application code.
- It can use code context to propose test cases and test implementation.
- Generated tests can accelerate coverage of normal and edge-case behavior.

##### 1.1.11.8.2 Verify Generated Tests
- A generated test can itself contain incorrect assumptions.
- Verify that assertions represent actual requirements rather than merely mirroring the current implementation.
- Run generated tests and inspect what behavior they genuinely validate.

##### 1.1.11.8.3 Skill Boundary
- Skill 1.1.7 covers writing and running unit tests as a development competency.
- Skill 1.1.11 covers Amazon Q Developer as an assistant in that process.
- Skill 3.3.6 later explicitly covers using Amazon Q Developer to generate automated tests, so detailed automated-test generation belongs there.

#### 1.1.11.9 Code Reviews

##### 1.1.11.9.1 Review Scope
- Amazon Q Developer can review code for security vulnerabilities and code-quality issues.
- Reviews can target code changes, a file, a project, or workspace according to the supported workflow.
- Current IDE review behavior can use git diff to identify recent changes.

##### 1.1.11.9.2 Review Types
- Amazon Q reviews use generative AI and rule-based automatic reasoning.
- AWS documents security and quality detectors as part of code reviews.
- Review findings can identify issues and propose remediation.

##### 1.1.11.9.3 Security Review
- Amazon Q code reviews include SAST capabilities.
- Examples of detectable vulnerabilities documented by AWS include SQL injection, cross-site scripting, and resource leaks.
- Security findings should be evaluated in the actual application context before applying a generated fix.

##### 1.1.11.9.4 Secrets Detection
- Amazon Q can identify secrets embedded in code or text files.
- Examples include hard-coded passwords and connection information.
- Remove exposed secrets from code and use an appropriate secrets/configuration mechanism.
- Detailed secret management belongs to Domain 2.

##### 1.1.11.9.5 Code Quality
- Amazon Q can identify code-quality issues in addition to security vulnerabilities.
- Findings should be treated as review input rather than automatically accepted changes.
- Validate recommendations against project conventions, architecture, performance requirements, and intended behavior.

#### 1.1.11.10 Review and Apply Fixes

##### 1.1.11.10.1 Investigate Finding
- Understand why Amazon Q reported an issue.
- Inspect the affected code and surrounding behavior.
- Determine whether the finding is applicable to the application's context.

##### 1.1.11.10.2 Generate Fix
- Amazon Q can propose code fixes for identified issues.
- Inspect the generated diff before applying it.
- Verify that the fix addresses the issue without introducing regressions.

##### 1.1.11.10.3 Validate
- Compile/build the application.
- Run relevant unit and integration tests.
- Re-run security/code review where appropriate.
- Review the final diff before commit or deployment.

#### 1.1.11.11 Code Transformations

##### 1.1.11.11.1 Transformation
- Amazon Q Developer can perform supported code transformations in IDEs.
- Current AWS documentation includes automated language and operating-system-level upgrades/conversions.
- The developer supplies the codebase and reviews generated changes before applying them.

##### 1.1.11.11.2 Java Transformation
- Amazon Q supports transformation workflows for supported Java applications.
- These capabilities can assist with language/runtime modernization.
- Do not memorize temporary version-support matrices unless they are specifically emphasized by current exam material.

##### 1.1.11.11.3 .NET Transformation
- Current Amazon Q Developer documentation also includes supported .NET transformation capabilities.
- The conceptual exam point is that Amazon Q can assist with modernization, not that every transformation is supported for every language/IDE.

#### 1.1.11.12 Documentation Assistance

##### 1.1.11.12.1 Generate Documentation
- Amazon Q can generate documentation from code.
- It can assist with README files and other project documentation.
- This can help explain code structure and behavior.

##### 1.1.11.12.2 Update Documentation
- Amazon Q can update existing documentation as code evolves.
- Generated documentation must still be reviewed for accuracy.
- Do not allow generated documentation to become a second, inconsistent source of truth.

#### 1.1.11.13 Context

##### 1.1.11.13.1 Context Matters
- Amazon Q's output is influenced by the context available to the feature.
- Relevant source files, selected code, workspace information, comments, and explicit instructions can improve relevance.
- Insufficient or ambiguous context can produce technically plausible but incorrect recommendations.

##### 1.1.11.13.2 Workspace Context
- Supported IDE workflows can use workspace context.
- This enables Amazon Q to reason beyond a single code snippet for broader development tasks.
- Context availability varies by feature and environment.

##### 1.1.11.13.3 Explicit Requirements
- State required behavior, constraints, runtime, AWS services, error handling, and acceptance criteria when relevant.
- Do not assume Amazon Q knows unstated project decisions.
- Better context reduces ambiguity but does not eliminate the need for validation.

#### 1.1.11.14 Responsible Use of Generated Code

##### 1.1.11.14.1 Human Review
- Review AI-generated code before accepting, committing, or deploying it.
- Check correctness, security, error handling, dependencies, and architecture.
- AI-generated output can be incomplete or incorrect even when it appears plausible.

##### 1.1.11.14.2 Testing
- Build and test generated changes.
- Unit tests should verify behavior.
- Integration tests should verify actual AWS service interactions where required.
- Passing generated tests alone does not prove that the implementation satisfies the original requirement.

##### 1.1.11.14.3 Security
- Do not provide sensitive information unnecessarily in prompts or development context.
- Generated code should follow least privilege, secret-management, encryption, and input-validation requirements.
- Security remains an application responsibility even when Amazon Q generates the implementation.

##### 1.1.11.14.4 Verify AWS Details
- AWS services, APIs, limits, and recommended practices change.
- Verify important service-specific generated guidance against current AWS documentation.
- Amazon Q assistance does not replace authoritative service documentation.

#### 1.1.11.15 Development Workflow

##### 1.1.11.15.1 Understand
- Ask Amazon Q to explain unfamiliar code, AWS APIs, errors, or architectural context.
- Use the explanation to form a hypothesis or implementation plan.
- Verify critical AWS facts when necessary.

##### 1.1.11.15.2 Generate
- Use inline suggestions, inline chat, normal chat, or agentic coding according to task size.
- Provide clear requirements and relevant project context.
- Keep generated changes scoped to the requested behavior.

##### 1.1.11.15.3 Review
- Inspect generated code and diffs.
- Use Amazon Q code review as an additional review mechanism.
- Do not confuse generated output with approved code.

##### 1.1.11.15.4 Test
- Generate or write tests.
- Run tests locally and through the project's normal validation process.
- Add missing tests for requirements that generated tests do not cover.

##### 1.1.11.15.5 Refine
- Give Amazon Q additional context or correction when output is incomplete.
- Iterate until the implementation satisfies requirements.
- Keep the developer responsible for the final technical decision.

#### 1.1.11.16 Choosing an Amazon Q Capability

##### 1.1.11.16.1 Need a Small Completion While Typing
- Use inline suggestions.
- Review and accept only useful generated code.

##### 1.1.11.16.2 Need to Modify Selected Code
- Use inline chat.
- Give a focused instruction such as fixing, refactoring, documenting, or testing the selected code.
- Review the generated diff.

##### 1.1.11.16.3 Need Explanation or Development Guidance
- Use chat.
- Supply relevant context and ask focused questions.

##### 1.1.11.16.4 Need a Larger Multi-File Development Change
- Use agentic coding where supported.
- Describe the desired outcome and constraints.
- Review all generated file and command changes.

##### 1.1.11.16.5 Need Security or Quality Analysis
- Use Amazon Q code review.
- Investigate findings and review proposed fixes before applying them.

##### 1.1.11.16.6 Need Modernization
- Use supported Amazon Q transformation capabilities.
- Review transformed code and validate it with the application's build/test process.

#### 1.1.11.17 Important Distinctions

##### 1.1.11.17.1 Suggestion vs Verified Implementation
- Amazon Q can generate an implementation.
- The developer must establish whether that implementation is correct.
- Generation and verification are separate steps.

##### 1.1.11.17.2 Code Generation vs Code Review
- Code generation creates or modifies implementation.
- Code review analyzes code for quality/security issues.
- The same assistant can support both activities, but they have different purposes.

##### 1.1.11.17.3 Inline Suggestion vs Agentic Coding
- Inline suggestion is immediate code completion based on local development context.
- Agentic coding handles broader tasks and can modify multiple project files.
- Choose the smallest capability appropriate to the task.

##### 1.1.11.17.4 Amazon Q Developer vs Amazon Q Business
- Amazon Q Developer is the AWS/development-focused assistant relevant to this exam.
- Amazon Q Business is a separate product focused on enterprise information and business assistance.
- Do not select Amazon Q Business for a scenario specifically asking for coding/development assistance.

##### 1.1.11.17.5 Amazon Q Developer vs General AWS SDK
- Amazon Q assists the developer in creating and understanding code.
- AWS SDKs are libraries the application itself uses at runtime to call AWS services.
- Amazon Q does not replace SDK clients or application runtime integrations.

- Amazon Q can generate unit tests and assist with test development.
- Core unit-testing competency belongs to Skill 1.1.7.
- Automated test generation with Amazon Q is explicitly revisited in Skill 3.3.6.

##### 1.1.11.18.2 AWS APIs and SDKs
- Amazon Q can help generate and explain code using AWS SDKs.
- Correct use of AWS APIs/SDKs remains Skill 1.1.9.

##### 1.1.11.18.3 APIs, Messaging, Streaming, and EventBridge
- Amazon Q can assist in implementing code for these AWS integration patterns.
- The actual AWS technical competencies remain Skills 1.1.6, 1.1.8, 1.1.10, and 1.1.12.

- Amazon Q can scan for security vulnerabilities and exposed secrets.
- IAM, authorization, encryption, secrets management, masking, and other application security responsibilities belong to Domain 2.

##### 1.1.11.18.5 Troubleshooting and Optimization
- Amazon Q can assist with debugging, refactoring, and optimization.
- The developer still needs the troubleshooting and optimization knowledge tested in Domain 4.
